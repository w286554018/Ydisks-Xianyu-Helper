# 商品平台同步删除 — 设计

## 已确认决策（Grill 8 问）
1. **动作范围**：下架 + 删除 两个都做（一次抓包拿两个 ground truth）
2. **操作规模**：列表多选 + 批量下架/删除（复用批量铺货后台任务骨架）；单商品操作保留
3. **失败语义**：平台成功才动本地；失败行保留原状 + 原因 + 可重试（重试复用批次 worker 的 retry-failed）
4. **数据模型**：item_info 增加 status 字段（迁移 00060，三方言）；下架商品保留展示 + 「已下架」徽标；同步时识别平台下架状态
5. **展示与操作矩阵**：已下架商品可重新上架（后置，视抓包结果定）、可删除；不允许编辑/复制发布/配规则；默认视图混排
6. **批量上限**：50 行/批（与批量铺货一致）；串行 + 5~10s 随机抖动；风控/会话失效立即中止本批次
7. **确认强度**：单商品删除=弹窗警告；批量删除=显示清单+输入「删除」二字防呆；批量下架=普通确认
8. **协议获取**：实机抓包（用户手动点 2 次，捕获页面自发请求），抓包前不写平台调用代码

## 架构分层（遵循 dependency-rules.md）
- internal/xianyu：新增 item 下架/删除 MTOP 调用（API 名与参数以抓包为准），走 mtop.Client 节流
- internal/application/items：ItemLifecycleService（单商品下架/删除编排 + 批量任务创建）；失败错误哨兵
- internal/db：迁移 00060 item_info.status；Items.AddStatus/状态查询方法
- internal/adapter：协议端口适配 + 批次 worker 中的生命周期动作类型
- internal/server：新端点（单商品 DELETE 语义变更 + 批量 lifecycle 批次端点）+ OpenAPI 契约
- frontend：表格/卡片操作按钮 + 多选 + 批量确认弹窗（防呆）+ status 徽标

## 与既有约束的对齐
- 零扇出：一次用户动作对应一次平台请求（单）或受控批次（批量 ≤50 串行）
- 会话失效/RGV587：立即中止、不自动重放
- 本地删除保留 deleted_at 审计语义不变；status 独立于软删除
