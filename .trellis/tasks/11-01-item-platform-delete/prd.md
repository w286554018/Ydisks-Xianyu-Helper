# 商品平台同步删除（item-platform-delete）

## 背景与问题
用户在系统中删除商品（垃圾桶按钮）时，当前实现是纯本地软删除（catalog_mutation.go Delete → db.Items.Delete 逻辑删除，保留审计历史）。协议层 internal/xianyu 从未实现平台删除接口。导致：
- 平台上商品依然在售，用户误以为已删除
- 下次全量同步时，被本地删除的商品会从平台数据重新出现

用户已确认方案 A：删除时真实调用闲鱼平台删除接口（单次、走账号级节流器），成功后再本地软删除。

## 核心需求（初稿，随 Grill 澄清更新）
1. 删除商品时先调用平台删除接口（具体 API 名称待协议抓包确认）
2. 平台删除成功后执行既有本地软删除（保留审计与恢复能力）
3. 单次用户操作对应最多一次平台请求，遵守 MTOP 节流铁律
4. 不可逆操作需要明确的用户确认交互
5. OpenAPI 契约、前端 UI、测试与覆盖率同步交付

## 待澄清问题
- 平台删除 API 的名称与参数（需协议抓包/页面 ground truth）
- 删除 vs 下架（下架可逆、删除不可逆）是否都要支持
- 平台删除失败时的本地行为（保留本地记录还是仍删除）
- 批量删除场景是否支持（当前 UI 是单商品删除）
- 会话失效/RGV587 风控时的处理路径
