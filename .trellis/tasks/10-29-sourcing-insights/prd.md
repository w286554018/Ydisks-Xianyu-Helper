# 选品参考：热词采集、关键词查货与 AI 文案

## Goal

为卖家提供日常选品参考能力：自动采集闲鱼平台搜索热词，按需单次查询关键词实时在售商品，
汇总自己店铺的真实畅销排行，并可对任一热词或商品生成上架文案与品类分析。

## 背景与已确认事实

调研阶段已通过只读探测验证以下事实，构成本需求的技术前提：

1. 闲鱼平台搜索接口为 `mtop.taobao.idlemtopsearch.pc.search`。以游客身份（无登录 cookie）
   直接访问搜索页时该接口返回 `RGV587_ERROR`，并被重定向到登录页，无法取得商品数据。
2. 注入已登录账号 cookie 的真实 Chromium 访问同一搜索页时，该接口返回
   `SUCCESS::调用成功`，单次搜索返回 30 条商品，页面可直接读取标题、价格、
   "多少人想要"、所在地区等字段。
3. 平台热词接口 `mtop.taobao.idlemtopsearch.pc.item.search.activate` 与
   `mtop.taobao.idlemtopsearch.pc.search.shade` 在**游客身份**下即可成功返回热词词条，
   不需要登录，也不需要搜索动作。
4. 用户账号数据库中的 cookie 以 AES-256-GCM 加密存储，密钥来自应用数据目录下的
   `data-key` 文件，解密需 `scope="cookie"` 与 `owner=<cookie_id>` 作为附加认证数据。

## 需求范围

### R1 平台热词每日采集

- 每日定时采集一次平台搜索热词，落库保存词条与采集时间。
- 该采集使用游客身份完成，**不携带任何账号凭证**，不经过账号级 MTOP 节流器。
- 单次采集最多发起 2 次出站请求（`search.activate` 与 `search.shade` 各至多 1 次）。
- 采集失败不得阻断系统其它功能，必须记录失败原因并在界面明确展示为"本次未取到"。
- 保留最近 30 天热词快照，超出部分按天清理。

### R2 关键词查货（单次手动触发）

- 用户在选品参考页输入关键词并**手动点击查询**，系统发起一次搜索并展示结果商品列表。
- 每次用户点击**最多对应 1 次搜索请求**，单次返回上限 30 条，不做自动翻页。
- 查询必须通过真实 Chromium 携带账号登录态完成，**禁止裸调搜索接口**。
- 查询结果展示：商品标题、价格、想要人数、地区、商品链接、商品 ID。
- 同一关键词在短时间内的重复点击需提示节流，禁止连续快速触发。
- 遇到风控（`RGV587`）、会话过期或登录失效时，立即终止本次查询并明确提示原因，
  不得重试、不得自动重放。

### R3 我的爆款榜

- 基于本地订单数据计算自己店铺的商品排行，**不产生任何平台请求**。
- 排序维度：销量与营收，时间窗口支持近 7 天与近 30 天切换。
- 每日随热词一同生成当日快照，保留最近 30 天。

### R4 AI 文案生成

- 提供两种文案模式：**上架文案**（可直接粘贴到发布页的标题与描述）与
  **品类分析**（该品类的卖点结构、定价区间、注意事项）。
- 复用系统现有 OpenAI 兼容 AI 配置（`ai_api_key`、模型设置），不新增独立 AI 配置项。
- 生成入口：热词条目、查询结果中的商品、我的爆款榜条目。
- AI 请求失败必须明确提示错误，不得返回伪造内容。

## 非目标

- 不做全自动定时抓取搜索商品列表。该行为违反项目 MTOP 频率铁律，明确排除。
- 不做搜索结果的自动翻页、批量多关键词轮询、并发抓取。
- 不把查询结果写入商品库，不与商品管理、自动化规则联动。
- 不做平台销量数据推算或伪造。

## 约束

- 所有平台出站请求必须遵守 `docs/architecture/` 与项目 `AGENTS.md` 的 MTOP 频率约束。
- 账号 cookie 只在内存中使用，禁止打印、写入日志、写入通知或返回给前端。
- 新增 HTTP 接口必须使用 `/api/v1` 前缀、命名 DTO、统一错误信封，并同步
  `api/openapi.yaml` 与前端生成类型。
- 前端遵循 `app -> features -> shared` 分层，组件不得直接调用 fetch。
- 所有新增函数、变量、状态必须有符合 `docs/architecture/comment-standard.md` 的中文语义注释。

## Acceptance Criteria

- [ ] 热词采集任务每日执行一次，单日出站请求不超过 2 次，采集结果可在页面查看。
- [ ] 游客身份采集热词时不携带账号 cookie，代码与测试可验证。
- [ ] 关键词查询为手动触发，单次点击最多产生 1 次搜索请求，返回商品数量上限 30。
- [ ] 查询走真实 Chromium 且携带账号登录态；存在测试证明未走裸 API 路径。
- [ ] 查询遇到 `RGV587` 时立即中止并提示，不重试、不自动重放，有对应测试。
- [ ] 我的爆款榜完全基于本地数据，测试证明该路径无平台出站请求。
- [ ] AI 两种模式均可生成且失败时明确报错，有成功与失败分支测试。
- [ ] 任何日志、接口响应、测试输出中均不出现明文 cookie 或 AI API Key。
- [ ] `make check` 相关门禁通过：`architecture`、`api-check`、`vet`、`lint`、`test`、`comments`。
- [ ] 前端构建成功并嵌入 `internal/webui/static`，页面可正常访问。

## Notes

- 热词接口在游客态可用，是本次方案中唯一允许自动化的平台请求来源。
- 搜索列表自动化被明确排除，原因见"非目标"一节。
